# LoomQ 小游戏开发流程 SOP

> 版本：v1.0 · 定稿：2026-08-19
> 目的：把"小游戏开发"从一次性创意变成可复制的流水线——**创意 → 定位 → 文案 → 方案 → 审校 → 实施 → 定稿 → 入库**。
> 适用：所有量子科普小游戏（伯特曼的袜子 / 施温格积木 / 斯特恩-盖拉赫 / 大富翁……）。
> 铁律：所有内容（文案/术语/颜色/玩法说明）一律模板化，词典 `web/qc_dict.py` 是唯一术语权威源，禁止 hardcode。

---

## 〇、流程总览（8 步，每步有产出物）

```
① 创意   → 一句话创意卡
② 定位   → 知识点 + 课程归属判断（放课程 or 放游戏汇总页）
③ 文案   → game_content/<id>.json（四段式：概念/典故/玩法/深挖）
④ 方案   → 技术方案（玩法机制 → 数据结构 → 交互 → 胜利判定）
⑤ 审校   → DeepSeek v4 pro 审方案 + 审文案
⑥ 实施   → 分步实现 + 真人互动迭代（每步确认）
⑦ 自检   → 可胜性自检 + 全站自检 + 静态审稿
⑧ 入库   → 挂课程/汇总页 + PRD/LOG 更新 + 存档
```

---

## 一、创意（产出：一句话创意卡）

每个游戏起手先写一张创意卡（仿伯特曼袜子）：

| 字段 | 示例（伯特曼袜子） |
|---|---|
| 游戏名 | 伯特曼的袜子 |
| 一句话创意 | 翻开一只袜子，用纠缠规则推理另一只 |
| 科普知识点 | 量子纠缠（Entanglement）|
| 背景出处 | Bell 1978《Bertlmann's Socks and the Nature of Reality》|
| 核心机制 | 配对翻牌：0=红袜/1=绿袜，同徽标+颜色规则配对 |
| 拟人/比喻 | 贝尔同僚伯特曼一红一绿袜——看到一只知道另一只 |

**创意卡写好 → 交用户确认创意方向，再进第②步。**

---

## 二、定位（产出：归属判断）

**判断"放课程还是放游戏汇总页"**：

1. 查 `web/content.py` 的 `COURSE` 树（当前 6 课）：
   - 第 1 课 叠加态：H 门（hgate）
   - 第 2 课 相位：转盘实验（bloch）
   - 第 3 课 纠缠：伯特曼的袜子（socks）
   - 第 4 课 测量：斯特恩-盖拉赫（sg，规划中）
   - 第 5 课 测量代数：施温格积木（schwinger，规划中）
   - 第 6 课 算法：量子大富翁（monopoly，规划中）

2. **匹配规则**：
   - 游戏知识点 = 某课主题 → **放课程**（游戏卡即课程卡，复用 `COURSE_NAV` 跳转）
   - 游戏知识点不在 6 课内，但前置概念已被某课覆盖 → **放量子游戏汇总页**（活动栏"量子游戏"），标注所属概念域
   - 游戏是纯背景/史实向（如贝尔不等式史）→ 放汇总页 + 词典引用

3. **产出**：明确写出"放课程 XX 课 / 放汇总页" + 理由。**交用户确认。**

## 三、文案（产出：`web/game_content/<id>.json`）

固定 schema（四段式，可扩展）：

```json
{
  "game": "socks",
  "title": "🧦 伯特曼的袜子",
  "subtitle": "用一只袜子，体验量子纠缠",
  "version": "2026-08-19",
  "sections": [
    {"id": "what",  "title": "一、什么是量子纠缠？", "type": "concept", "body": "...", "dict_refs": ["entanglement", "qubit"]},
    {"id": "story", "title": "二、典故由来",         "type": "story",   "body": "...", "dict_refs": ["John Bell"]},
    {"id": "howto", "title": "三、这个游戏怎么玩",   "type": "howto",   "body": "...", "dict_refs": []},
    {"id": "sci",   "title": "四、科学意义",         "type": "deeper",  "body": "...", "dict_refs": []}
  ],
  "source_refs": ["bell-1978"]
}
```

**写作规范**：
- 所有术语从 `qc_dict.py` 取（中英解释），正文出现词典名词 → 前端自动链接化
- 中文版行文"中文(英文)"；英文版"仅英文"
- 玩法 section 必须写清：**颜色/值规则 → 操作步骤 → 获胜条件**（玩家零困惑）
- 文案写到可交付，**交用户确认后再进方案**

## 四、技术方案（产出：方案文档）

基于"怎么玩"设计，覆盖 5 层：

| 层 | 内容 | 袜子示例 |
|---|---|---|
| 数据结构 | state / 牌面 / 配对关系 | `pairs[{id,bits}]` + `board[{pairId,side,bit,color,flipped}]` |
| 玩法机制 | 翻牌规则 / 匹配判定 / 模式 | 同徽标+颜色规则；same/diff 双模式 |
| 交互 | 事件委托 / 防重复绑定 | document 级委托（面板动态重建） |
| 胜利判定 | 何时胜 / 用时 / 反馈 | matched==total → 胜利横幅+计时 |
| 可胜性 | 证明牌局必可胜 | `selfcheck_socks.py` 800 局模拟 |

**必须包含**：可胜性证明方案（游戏逻辑必须机器可验证，接入 selfcheck）。

---

## 五、审校（DeepSeek v4 pro）

两类审校，全部走独立提示词文件（`prompts/*.yaml`）：

1. **方案审校**：把技术方案发给 DS v4 pro，重点审——玩法是否有死局 / 规则是否自洽 / 是否面向零基础 / 是否漏掉边界
2. **文案审校**：`python scripts/review_content.py --llm`（静态检查 + LLM 审稿），对照词典审准确性/一致性/交叉引用

审校结果**人工确认**后进入实施。注：LLM 审稿需 `config/user_key.json` 配置有效 `sk-` key。

---

## 六、实施（产出：可运行代码 + 真人互动迭代）

**铁律：分步实施，每步暂停等真人确认，绝不连跑。**

标准步骤：
1. 游戏本体 JS（如 `web/static/js/<game>.js`），独立 IIFE + `init()`，事件委托防重复绑定
2. 前端面板（动态渲染进 `#game-play`，游戏永不折叠）
3. 配色走 `colors.js` + CSS 变量（禁硬编码色号）
4. 文案 JSON 挂载（/api/game-content 自动读取）
5. 词典素材引用（dict_refs → 弹小窗）
6. 胜利判定 + 计时器
7. playwright 实测截图，逐交互验证

**每个游戏一个 JS 文件，复用 app.js 的 openGame 模板。**

---

## 七、自检（产出：全绿证据）

固定 4 件套（接入 `web/selfcheck.sh`）：
1. **可胜性自检**：`web/selfcheck_<game>.py`（模拟 N 局证明必可胜）
2. **全站自检**：`bash web/selfcheck.sh`（术语黑名单/可胜性/服务/按钮/零错误）
3. **静态审稿**：`python scripts/review_content.py`（JSON+词典一致性）
4. **LLM 审稿**（可选）：`--llm`

---

## 八、入库（产出：正式上线的游戏）

1. **放课程**：`content.py` COURSE 加课程卡 + COURSE_NAV 加跳转 → 游戏卡进"互动课程"
2. **放汇总页**：`app.js` GAME_LIST 加卡 → 进"量子游戏"活动栏视图
3. 更新 `docs/PRD.md`（活动栏/功能清单/版本记录）+ `LOG.md`
4. 游戏文案 JSON 存档（内容生产流程闭环）

---

## 九、基建清单（开发新游戏时全部复用，零重造）

| 基建 | 位置 | 用途 |
|---|---|---|
| 词典（唯一权威源） | `web/qc_dict.py` | 术语/定义/素材/别名黑名单 |
| 内容生产流程 | `web/game_content/*.json` + `/api/game-content/<id>` | 文案模板化 |
| 词典小窗 | `/api/dict/<en>` + modal | 词条点击弹窗 |
| 配色 | `colors.js` + CSS 变量 | 全站单一色板 |
| 审稿 | `scripts/review_content.py` + `prompts/content_review_v1.yaml` | 静态+LLM 审稿 |
| 自检 | `web/selfcheck.sh` | 全站自检 |
| 游戏视图 | `app.js` openGame + GAME_LIST | 统一挂载 |
| 课程树 | `content.py` COURSE + COURSE_NAV | 课程归属 |
