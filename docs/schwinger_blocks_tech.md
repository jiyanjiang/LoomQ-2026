## 一、玩法机制（核心）

**任务形态：关卡制**——每关给出入射粒子态 + 一串积木（投影算符），判断"粒子能否通过"（通过 / 挡住），答对即过关并讲解原理。最后一关为挑战：给目标（挡住粒子），自己拼积木串。

**判定规则（数学上完全确定）**：
- 每块积木 = 2×2 投影矩阵（计算基）
- 光从左边射入，依次穿过每块积木（= 算符连乘）
- **相邻两块积木所代表的态正交 → 光被挡（概率 0）**
- **非正交 → 光透过（概率 > 0）**
- 透过率量化（进阶）：首块 1/2，之后每块乘 |⟨后一态|前一态⟩|²
- **概率性表述**：UI 一律用"透（有概率）/ 挡（概率 0）"，**不说"必然透"**——避免误导（原教具是概率性实验）

**四种积木**（还原量子玩具核心 4 块，全部 spin-1/2）：

| 积木 | 矩阵 | 精确定义 | 矩阵元 |
|---|---|---|---|
| \|↑⟩⟨↑\| | [[1,0],[0,0]] | S_z 本征值 **+ħ/2** 本征态（z 向上）| \|↑⟩=(1,0)ᵀ |
| \|↓⟩⟨↓\| | [[0,0],[0,1]] | S_z 本征值 **−ħ/2** 本征态（z 向下）| \|↓⟩=(0,1)ᵀ |
| \|+⟩⟨+\| | ½[[1,1],[1,1]] | S_x 本征值 **+ħ/2** 本征态（x 方向 +）| \|+⟩=(↑+↓)/√2 |
| \|−⟩⟨−\| | ½[[1,−1],[−1,1]] | S_x 本征值 **−ħ/2** 本征态（x 方向 −）| \|−⟩=(↑−↓)/√2 |

> **符号约定（零歧义）**：\|↑⟩/\|↓⟩ 是 S_z 的本征态（S_z 对角基）；\|+⟩/\|−⟩ 是 S_x 的本征态，在 S_z 基下展开为 (↑±↓)/√2。自旋"方向"严格用 S_z/S_x 的 ±ħ/2 本征值定义，**不用"左/右"这种有坐标歧义的词**。
>
> **正交性根源**：⟨↑\|↓⟩=0（S_z 内正交）；⟨↑\|+⟩=1/√2≠0（跨 z/x 非正交）。判定表全部由此推出。

**相邻正交判定表**（游戏核心表，可胜性自检的依据）：

| 前\后 | \|↑⟩ | \|↓⟩ | \|+⟩ | \|−⟩ |
|---|---|---|---|---|
| \|↑⟩ | 透 | **挡** | 透 | 透 |
| \|↓⟩ | **挡** | 透 | 透 | 透 |
| \|+⟩ | 透 | 透 | 透 | **挡** |
| \|−⟩ | 透 | 透 | **挡** | 透 |

> 只横向相邻判定（每对相邻块）。整串只要有一处相邻正交 → 挡；否则透。

## 二、关卡设计（8 关渐进，教学阶梯）

| 关 | 积木串 | 答案 | 教学点 |
|---|---|---|---|
| 1 | [\|↑⟩⟨↑\|] | 透 | 单块投影，概率 1/2 |
| 2 | [\|↑⟩⟨↑\|, \|↑⟩⟨↑\|] | 透 | 幂等性：\|↑⟩⟨↑\|²=\|↑⟩⟨↑\| |
| 3 | [\|↑⟩⟨↑\|, \|↓⟩⟨↓\|] | **挡** | 排他原理：正交投影相乘=0 |
| 4 | [\|+⟩⟨+\|, \|−⟩⟨−\|] | **挡** | 排他原理（x 基同样成立）|
| 5 | [\|↑⟩⟨↑\|, \|+⟩⟨+\|] | 透 | 不同基非正交，概率 1/4 |
| 6 | [\|+⟩⟨+\|, \|↓⟩⟨↓\|] | 透 | 同 5，方向反过来 |
| 7 | [\|↑⟩⟨↑\|, \|+⟩⟨+\|, \|↓⟩⟨↓\|] | **透！** | ★z→x→z 非对易核心谜题 |
| 8 | 目标"挡"，自由拼 2-3 块 | 多种解 | 挑战：正交组合的构造 |

**第 7 关是灵魂**：中间插一块 x 方向投影，z 的结果被"打乱"，光居然透过——非对易性 [σz, σx]≠0 的直观演示。

## 三、数据结构（schwinger.js 内部）

```js
const state = {
  level: 1,            // 当前关 1-8
  blocks: [],          // 玩家当前拼的积木串 [{id:"up"}...]
  target: "pass",      // 本关目标：pass(透) / block(挡)
  correct: 0,          // 已过关卡数
};
// 预置关卡表（不可变，含答案）
const LEVELS = [
  { target: "pass",  blocks: ["up"] },
  { target: "pass",  blocks: ["up", "up"] },
  { target: "block", blocks: ["up", "down"] },
  ...
];
```

**判定函数**（纯函数，供自检复用）：
```js
function isOrthogonal(a, b) { return ORTHO[a][b]; }  // 查表
function passes(blocks) {
  for (let i = 0; i + 1 < blocks.length; i++)
    if (isOrthogonal(blocks[i], blocks[i+1])) return false;
  return true;
}
```

## 四、交互设计

- **积木托盘**：4 种积木（|↑⟩⟨↑| / |↓⟩⟨↓| / |+⟩⟨+| / |−⟩⟨−|）可点击加入拼串区
- **拼串区**：当前积木顺序展示（还原"拼接"动作）
- **光学动画**：SVG 一条光线从左侧射入，穿过每块积木；遇正交 → 光在积木处反弹（❌），否则透出（✅）
- **判断按钮**：选"光透过"或"光被挡住" → 判分 + 原理讲解
- **原理讲解**：每次判定后给出狄拉克记号算式 + **通俗解读**（固定模板，竞赛要求，水果类比）：
  - **水果模型**：两套分类标准——颜色（黄=z+ / 绿=z−）、形状（香蕉=x+ / 苹果=x−）
  - **挡**："先筛出黄色的，再从里面筛绿色的——同一套标准（颜色）里互斥，黄色水果里没有绿色的（⟨↑|↓⟩=0，两向量垂直）"
  - **透**："先筛出黄色的，再从里面筛香蕉形状的——颜色和形状是两套不同标准，黄色水果里一定有黄香蕉（⟨↑|+⟩=1/√2≠0，概率 1/2）"
  - **幂等（同积木连用）**："同一台筛子筛两次，筛过的还是它自己——|↑⟩⟨↑|²=|↑⟩⟨↑|，所以两个 |↑⟩⟨↑| 连用还是透（幂等性）"
  - **z→x→z 谜题关键**："经典筛子不会改变水果的颜色，但量子筛子会——筛'香蕉形状'时把'颜色'也打乱了（测量 x 扰动 z），所以最后再筛绿色仍有光透过"
  - 规则：每块积木=一台筛子；不相容=正交=垂直向量互不包含彼此分量；z±（颜色）与 x±（形状）是两套相容的分类标准

## 六、可胜性自检（selfcheck_schwinger.py）
